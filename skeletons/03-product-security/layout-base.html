Three pillars

Reachability, provenance, response

Reachability, not counts

A vulnerable function that no code path calls is reported, ranked last, and never pages anyone at 3am.

Build provenance

Every artefact carries a signed statement of how it was built, so an unreproducible image is a build failure, not a surprise.

A patch, not a ticket

Where a safe version exists, you get the exact version bump as a reviewable diff against your own lockfile.

Straight answers

The questions a security reviewer asks first

Does Bastion need my source code?

It needs your manifest files and a call graph, both of which it computes from a shallow checkout you delete afterwards.

Where does the advisory data come from?

Public databases, plus maintainer advisories we mirror, with the ingest timestamp shown on every finding.

What if a finding is a false positive?

Suppress it in the policy file with a reason and an expiry date. Suppressions without an expiry are rejected.
